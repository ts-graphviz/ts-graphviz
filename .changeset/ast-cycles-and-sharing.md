`stringify`, `toModel` and `fromModel` (and so `toDot`) reject a structure that contains itself and limit how far shared nodes multiply the work. An AST or model built in code (or by `structuredClone` or a custom deserialiser) can contain itself, such as a subgraph among its own statements (`s.addSubgraph(s)`): `stringify` printed it until memory ran out, and `toModel` / `fromModel` ran out of call stack with an uncoded `RangeError`. They now throw a `TypeError` with code `TSG_ERR_CYCLIC_STRUCTURE`. Such an AST can also hold one node object in several places, and each place is printed or converted again: a node held twice at each of k levels was written 2^k times. The new `maxSharedNodes` option of `stringify` / `Printer` and of `toModel` (default 100 000, `0` disables) counts every time a node object is reached after the first. Past it, they throw a `RangeError` with code `TSG_ERR_SHARED_NODE_COUNT_EXCEEDED`. An AST without shared nodes, such as a parsed one, is never counted; `fromModel` already counts every AST node it makes toward `maxASTNodes`. Both codes are new entries in `ERROR_CODES`. `toModel` also collects the nodes of each subgraph once instead of walking every level below it again, so nested subgraphs no longer take time quadratic in their depth.

The error for an AST node or model that no plugin handles names only its type: it no longer copies the whole node into the message, and a node that cannot be serialised or a type that is not a string no longer replaces the `TSG_ERR_NO_PLUGIN` error with an uncoded `TypeError`. The errors for an attribute list kind, a port and a compass point quote at most the first 64 characters of the value.
