Adapter: `toBlob` replaces `toStream` and `toFile`, typed browser entry, `CommandExecutionError`, models as input

- **Breaking:** `toStream` and `toFile` are removed. `toBlob(dot, options)` renders with the same options and returns the output as a `Blob`, on Node.js and Deno alike. The output is held in memory (up to `maxOutputSize`), and the Blob is returned once the command has succeeded, so every failure rejects the call before anything is read. Its `type` is the media type of the format (`image/svg+xml`, `image/png`, `application/pdf`, `application/json`, `text/vnd.graphviz`, …; a renderer variant such as `png:cairo` gets the type of `png`), or empty for a format without a well-known one. Read it with `blob.text()`, `blob.arrayBuffer()` or `blob.stream()`, or pass it to `new Response(blob)`.
  - For `toStream`, use `(await toBlob(dot, options)).stream()`, a Web `ReadableStream<Uint8Array>`. In 3.x the Node.js entry returned a Node.js stream; for the Node stream API, use `Readable.fromWeb(blob.stream())`.
  - For `toFile`, write the output where your application decides: `await writeFile(path, (await toBlob(dot, options)).stream())` (`node:fs/promises`) or `await Deno.writeFile(path, (await toBlob(dot, options)).stream())`. The adapter no longer writes files, so on Deno it needs no `--allow-write`.
  - Show an SVG Blob as an image (`<img src>`): a `blob:` URL of `image/svg+xml` opened as a document runs with your application's origin.
- The browser entry has the real `Options`/`Layout` types instead of `any` and re-exports the type definitions, so misuse is a type error; it throws an `Error` with `code: 'TSG_ERR_UNSUPPORTED_ENVIRONMENT'`.
- Failures of the Graphviz command reject with the new `CommandExecutionError` (an `Error` with `code: 'TSG_ERR_COMMAND_FAILED'`, exported by the Node.js and Deno entries) with `command` and, when the command started, `exit` (`code`, `signal` as `string | null`, `stderr`); `exit` is `undefined` when it could not start, so check it before reading its fields. `cause` holds the underlying error, when there is one. Its message holds at most 256 characters of the command and 1024 characters of the detail (the exit status and the start of the kept stderr), with a note of how much was left out, and writes C0 controls other than tab and line feed, DEL, C1 controls, lone surrogates, the line and paragraph separators and the bidirectional formatting characters as `\xNN` / `\uNNNN`; the output-limit `RangeError` does the same for the command. `exit.stderr` keeps the last 64 KiB of the command's stderr, decoded as UTF-8 and not escaped. The message and `exit.stderr` can contain file paths and parts of the DOT source; do not show them to end users verbatim. In 3.x the Node.js entry rejected with a bare `Error` (for the Deno entry, see the process controls note).
- `ts-graphviz/adapter`: `toBlob` also accepts a model (root graph, `Dot`, node, edge or subgraph) and render it with `toDot` first.
